# AlertEscalation

Асинхронный анализ личных сообщений через Kurigram и Typesafe.

## Запуск

Требуются Python 3.14+ и uv:

```sh
uv sync
```

Задайте переменные окружения (значения ниже — примеры):

```sh
export TYPESAFE_API_KEY='your-api-key'
export USER_ID=8074350454
export HISTORY_SIZE=15
uv run python -m alertescalation
```

`USER_ID` необязателен: без него обрабатываются личные сообщения во всех диалогах. `HISTORY_SIZE` по умолчанию равен 15 и должен быть не меньше 5
(`MIN_MESSAGES`). `TYPESAFE_BASE_URL` позволяет изменить адрес API.
Файл `.env` автоматически не загружается. Для него можно использовать
`uv run --env-file .env python -m alertescalation`.

Также доступна команда `uv run alertescalation`. При первом запуске Kurigram
запросит авторизацию Telegram для существующей конфигурации сессии `MySession`.

## Регистрация обработчиков

В асинхронной точке входа используйте уже созданные `app` и `monitor`:

```python
from alertescalation.handlers import register_handlers

register_handlers(app, monitor)
```

Регистрация выполняется один раз до запуска клиента. Функция вызывает
`app.add_handler(MessageHandler(...))` с асинхронной обёрткой. При необходимости
можно передать `user_id=123` и `history_size=20`; `user_id=None` отключает ограничение
по пользователю. Фильтры допускают входящие и исходящие личные сообщения. `USER_ID`
ограничивает обработку диалогом с указанным пользователем. Сообщения без текста или подписи пропускаются.

Каждый диалог хранится в отдельном `deque(maxlen=...)` в замыкании обработчика.
`asyncio.Lock` последовательно выполняет добавление и анализ в пределах диалога;
разные диалоги могут анализироваться параллельно. Монитор получает историю явно.
История хранится в памяти до завершения процесса. Исходящие сообщения добавляются в ту же историю с ID своего отправителя.

После накопления `MIN_MESSAGES` монитор обращается к API через `httpx.AsyncClient`.
При превышении порога записывается предупреждение с ID чата и оценкой; при
настроенном боте также отправляется уведомление в Telegram. Ошибки анализа логируются без содержимого
переписки, отмена coroutine распространяется штатно. При завершении приложения
HTTP-клиент закрывается в `finally`.

Для совместимости с benchmark сохранены `monitor.history`, `add_message(role,
content)` и `analyze()`; обработчики используют отдельные истории через аргумент
`history`.

## Алерты через бота

Задайте обе переменные окружения:

```sh
export BOT_TOKEN='your-telegram-bot-token'
export ALERT_CHAT_ID='your-recipient-chat-id'
```

Получатель должен заранее открыть диалог с ботом и нажать Start (для группы —
добавить бота с правом отправки сообщений). При каждом результате не ниже
`ALERT_THRESHOLD` бот отправит ID исходного чата и оценку через Telegram Bot API.
Текст переписки не отправляется. Без обеих настроек остаются предупреждения в логе;
если задана только одна настройка, запуск завершается с ошибкой конфигурации.
При собственной регистрации передайте `alerts=BotAlerts(http_client, token, chat_id)`
в `register_handlers`; жизненным циклом `httpx.AsyncClient` управляет вызывающий код.

## Отладочный режим

Добавьте `DEBUG_MODE=true` в `.env` и перезапустите приложение. Каждое входящее или исходящее
текстовое сообщение или подпись анализируется начиная с первого сообщения,
без ожидания `MIN_MESSAGES`. Полный набор оценок и итоговый балл записываются
в лог и отправляются в настроенного бота независимо от порога. Отдельный алерт
для того же результата не дублируется. По умолчанию режим выключен.

## Дельта и подавление алертов

Для каждого диалога отдельно сохраняются последние `ALERT_TREND_MESSAGES`
успешные оценки (по умолчанию 5). Первый алерт отправляется, если первая оценка
не ниже `ALERT_THRESHOLD`. Последующие алерты отправляются при росте итогового
балла относительно предыдущей оценки. Высокий, но неизменный или снижающийся
балл не вызывает повторных алертов.
Если балл снизился минимум на `ALERT_DROP` (по умолчанию 0.15) относительно
оценки пять анализируемых сообщений назад, алерт подавляется независимо
от порога и последнего изменения. Например, для последовательности
0.70 → 0.68 → 0.64 → 0.60 → 0.58 → 0.55 последнее уведомление подавляется.
До накопления пяти предыдущих оценок подавление по окну недоступно;
снижение или отсутствие роста всё равно не вызывает повторных алертов.
Сообщения без результата анализа не добавляют оценку в историю дельт.
Алерты содержат дельту к предыдущей оценке и дельту за настроенное окно.
В режиме отладки отчёт приходит всегда и содержит поле «Алерт: да/нет».

Это стартовые параметры, а не подтверждённый оптимум: снижение на 0.15 за
пять сообщений делает подавление менее чувствительным к малым колебаниям.
Для настройки на реальных диалогах переопределите в `.env`:

```dotenv
ALERT_DROP=0.15
ALERT_TREND_MESSAGES=5
```
